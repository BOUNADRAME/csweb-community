# Webhooks & Intégration API

Intégrez CSWeb avec vos applications tierces pour piloter le breakout, gérer les logs et automatiser vos workflows.

import { Callout } from 'nextra/components'

<Callout type="info">
Vos applications appellent CSWeb avec un jeton, **sans compte CSWeb** : pour
piloter et suivre le breakout, lire les journaux et lire les médias. CSWeb
n'envoie pas d'événements vers vos systèmes.
</Callout>

---

## Cas d'Usage

### 1. Piloter le Breakout depuis une Application Tierce

Déclenchez le breakout sélectif d'un dictionnaire spécifique depuis votre dashboard ou application de monitoring.

**Exemple :** Application de supervision qui lance automatiquement le breakout du dictionnaire `MENAGE` quand 1000 nouveaux questionnaires sont détectés.

### 2. Centraliser les Logs dans un SIEM

Envoyez les logs CSWeb vers votre système de monitoring externe (ELK Stack, Splunk, Datadog).

**Exemple :** Alertes automatiques sur échecs de breakout ou erreurs de synchronisation.

### 3. Intégration BI/Dashboard

Récupérez les métriques de collecte en temps réel pour alimenter vos dashboards Power BI, Tableau ou Grafana.

**Exemple :** Dashboard affichant le nombre de questionnaires par région, taux de synchronisation, progression du breakout.

## Webhooks racine

CSWeb expose 5 endpoints PHP à la racine, pilotables depuis vos systèmes
externes (plateforme, scripts cron, monitoring, BI), sans compte utilisateur
CSWeb. Tous partagent :

- **Auth** : `Authorization: Bearer <jeton>`, **un jeton par webhook** depuis
  8.0.14 / 8.1.20 (voir [Configuration](#configuration))
- **Format de réponse uniforme** :
  ```json
  { "success": true,  "data": ... | null, "error": null,             "meta": {...}? }
  { "success": false, "data": null,        "error": { "code": "...", "message": "..." } }
  ```
- **Rate-limit** : 60 requêtes / minute par couple (webhook, jeton, IP), réglable
  avec `WEBHOOK_RATE_LIMIT_PER_MIN`
- **Pas de cache** : chaque réponse porte `Cache-Control: no-store`
- **Body POST max** : 64 KB

| Endpoint                          | Méthode    | Rôle                                                  | Doc                                             |
|-----------------------------------|------------|-------------------------------------------------------|-------------------------------------------------|
| `/breakout-webhook.php`           | POST       | Déclencher un breakout pour un dictionnaire           | Voir ci-dessous                                 |
| `/breakout-status-webhook.php`    | GET        | Statut breakout par dictionnaire (paginé)             | [→ détails](/reference/api/breakout-status)     |
| `/dictionary-schema-webhook.php`  | GET / POST | CRUD sur la configuration des cibles breakout         | Voir ci-dessous                                 |
| `/log-reader-webhook.php`         | GET        | Lire les fichiers de log CSWeb                        | Voir ci-dessous                                 |
| `/media-webhook.php`              | POST       | Lister et lire les médias (audio, photos)             | [Voir ci-dessous](#médias-audio-photos)         |

### Déclencher un breakout

```bash
curl -X POST http://csweb.example.com/breakout-webhook.php \
  -H "Authorization: Bearer $WEBHOOK_TOKEN_BREAKOUT" \
  -H "Content-Type: application/json" \
  -d '{"dictionary": "MENAGE_DICT"}'
```

**Réponse (succès)** :

```json
{
  "success": true,
  "data": {
    "dictionary": "MENAGE_DICT",
    "exitCode": 0,
    "output": "Processed 1500 cases…",
    "stderr": "",
    "durationMs": 45230,
    "logFile": "MENAGE_DICT_20260321_103015-api.log"
  },
  "error": null
}
```

`output` et `stderr` sont **tronqués à 4 KB** par défaut. Pour le contenu
complet, soit lire `data.logFile` via `log-reader-webhook.php`, soit poser
`BREAKOUT_WEBHOOK_VERBOSE=1` côté serveur.

### Lire le statut consolidé d'un breakout

Voir la page dédiée : [Breakout Status Webhook](/reference/api/breakout-status).

### Lister / lire les logs

```bash
# Lister les logs disponibles
curl -H "Authorization: Bearer $WEBHOOK_TOKEN_LOGS" \
  "http://csweb.example.com/log-reader-webhook.php?action=list"

# Lire les 200 dernières lignes d'un fichier
curl -H "Authorization: Bearer $WEBHOOK_TOKEN_LOGS" \
  "http://csweb.example.com/log-reader-webhook.php?file=ui.log&lines=200"
```

Restrictions :
- Seuls les fichiers matchant `^[a-zA-Z0-9._-]+\.log$` sont exposés.
- Le fichier doit physiquement résider dans `var/logs/` (pas de symlink échappant).
- `lines` borné à 5000.

### Configurer la cible breakout d'un dictionnaire

```bash
# Enregistrer (ou mettre à jour) la cible — par dict_name OU dict_id
curl -X POST http://csweb.example.com/dictionary-schema-webhook.php \
  -H "Authorization: Bearer $WEBHOOK_TOKEN_SCHEMA" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "register",
    "dictionary_name": "MENAGE_DICT",
    "host_name": "host.docker.internal",
    "schema_name": "menage_breakout",
    "schema_user_name": "csweb",
    "schema_password": "<secret>"
  }'

# Lire la config existante
curl -H "Authorization: Bearer $WEBHOOK_TOKEN_SCHEMA" \
  "http://csweb.example.com/dictionary-schema-webhook.php?action=list"

# Supprimer la config (par nom OU id)
curl -X POST http://csweb.example.com/dictionary-schema-webhook.php \
  -H "Authorization: Bearer $WEBHOOK_TOKEN_SCHEMA" \
  -H "Content-Type: application/json" \
  -d '{"action": "unregister", "dictionary_name": "MENAGE_DICT"}'
```

Le `schema_password` est stocké chiffré (`AES_ENCRYPT(?, 'cspro')`) en base.

### Médias (audio, photos)

Disponible depuis **8.0.14 / 8.1.20**. Pour une plateforme qui doit lire les
médias déposés par l'application CSPro **sans compte CSWeb**.

- Toujours en `POST`, le chemin dans le **corps JSON** : il n'apparaît jamais
  dans une URL ni dans un journal d'accès.
- Limité aux dossiers de `MEDIA_WEBHOOK_PREFIXES` et aux extensions de
  `MEDIA_WEBHOOK_EXTENSIONS`. Les médias peuvent être répartis dans plusieurs
  dossiers (par exemple `praps2/media/` et `sondage_audio/`) : listez-les tous,
  séparés par des virgules. N'y mettez jamais `apps/`, qui contient les
  applications CSPro. Un chemin avec `..`, un chemin absolu ou une
  extension non autorisée est refusé (400) ; un chemin hors des dossiers
  autorisés, y compris par un lien symbolique, est refusé (403).
- Jeton propre obligatoire (`WEBHOOK_TOKEN_MEDIA`) : le jeton commun n'ouvre
  jamais ce webhook.
- **Pas de suppression par défaut** : l'action `delete` répond
  `403 delete_disabled` tant que `MEDIA_WEBHOOK_ALLOW_DELETE` ne vaut pas `1`.

```bash
# Dossiers autorisés (ceux de MEDIA_WEBHOOK_PREFIXES qui existent)
curl -X POST "https://csweb.example.org/media-webhook.php" \
  -H "Authorization: Bearer $WEBHOOK_TOKEN_MEDIA" \
  -H "Content-Type: application/json" \
  -d '{"action": "list"}'
# → data: {"dossiers": ["praps2/media", "sondage_audio"]}

# Tous les médias d'un dossier et de ses sous-dossiers (pays…)
#   {"action": "list", "dossier": "praps2/media", "recursif": true}
# → chaque fichier porte son "chemin", à passer tel quel à "read".
#   Au plus 5 000 fichiers par appel ("tronque": true au-delà : lister par sous-dossier).

# Lister un dossier
curl -X POST "https://csweb.example.org/media-webhook.php" \
  -H "Authorization: Bearer $WEBHOOK_TOKEN_MEDIA" \
  -H "Content-Type: application/json" \
  -d '{"action": "list", "dossier": "praps2/media/1"}'
# → {"success":true,"data":{"dossier":"praps2/media/1",
#     "fichiers":[{"nom":"…_ENTRETIEN.m4a","chemin":"praps2/media/1/…_ENTRETIEN.m4a","octets":482113,"md5":"…","modifie":"2026-11-25T09:56:38+00:00"}],
#     "dossiers":[],"tronque":false}, "error":null}

# Lire un fichier (contenu en base64 + empreintes du fichier entier)
curl -X POST "https://csweb.example.org/media-webhook.php" \
  -H "Authorization: Bearer $WEBHOOK_TOKEN_MEDIA" \
  -H "Content-Type: application/json" \
  -d '{"action": "read", "chemin": "praps2/media/1/…_ENTRETIEN.m4a"}'
# → data: {"octets":482113,"sha256":"…","md5":"…","type":"audio/mp4",
#          "offset":0,"longueur":482113,"contenu":"<base64>","contenu_sha256":"…"}

# Fichier plus gros que MEDIA_WEBHOOK_MAX_BYTES : lire par morceaux
#   {"action": "read", "chemin": "…", "offset": 0,        "longueur": 10485760}
#   {"action": "read", "chemin": "…", "offset": 10485760, "longueur": 10485760}
# Une lecture d'un seul tenant trop grosse répond 413 avec data.octets (taille totale).

# Métadonnées seules
#   {"action": "info", "chemin": "…"}

# Supprimer : désactivé par défaut (403 delete_disabled).
# Avec MEDIA_WEBHOOK_ALLOW_DELETE=1 : corbeille CSWeb (restaurable dans le File Manager)…
#   {"action": "delete", "chemin": "…"}
# …ou effacement définitif (droit à l'effacement)
#   {"action": "delete", "chemin": "…", "definitif": true}
# → data: {"supprime": true, "mode": "corbeille" | "definitif"}
```

Vérifiez toujours l'empreinte : `sha256` décrit le fichier entier,
`contenu_sha256` le morceau renvoyé. Chaque appel est consigné dans
`var/logs/media-webhook.log` avec une empreinte du chemin, jamais le chemin.

## Configuration

### Variables d'environnement

Depuis 8.0.14 / 8.1.20, chaque webhook a son propre jeton. Toutes ces
variables sont déjà dans `.env.example` :

| Variable | Webhook | Défaut |
|---|---|---|
| `WEBHOOK_TOKEN_BREAKOUT` | `breakout-webhook.php` | jeton commun |
| `WEBHOOK_TOKEN_STATUS` | `breakout-status-webhook.php` | jeton commun |
| `WEBHOOK_TOKEN_SCHEMA` | `dictionary-schema-webhook.php` (peut changer la base cible : à protéger en priorité) | jeton commun |
| `WEBHOOK_TOKEN_LOGS` | `log-reader-webhook.php` | jeton commun |
| `WEBHOOK_TOKEN_MEDIA` | `media-webhook.php` | **aucun** : webhook fermé (503) |
| `BREAKOUT_WEBHOOK_TOKEN` | jeton commun des versions précédentes | — |
| `WEBHOOK_RATE_LIMIT_PER_MIN` | tous | `60` |
| `MEDIA_WEBHOOK_PREFIXES` | médias : dossiers autorisés, séparés par des virgules (ex. `praps2/media/,sondage_audio/`) | **aucun** : webhook fermé (503) |
| `MEDIA_WEBHOOK_EXTENSIONS` | médias : extensions autorisées | `m4a,jpg,jpeg,png` |
| `MEDIA_WEBHOOK_MAX_BYTES` | médias : taille maximale d'une lecture | `20971520` (20 Mio) |
| `MEDIA_WEBHOOK_ALLOW_DELETE` | médias : autoriser l'action `delete` | `0` (désactivée) |

Quand le jeton d'un webhook est défini, **seul ce jeton** l'ouvre. Laissé vide,
le jeton commun `BREAKOUT_WEBHOOK_TOKEN` reste accepté : une mise à jour ne
casse rien. Sans aucun jeton, le webhook répond `503 server_misconfigured`.
Aucun jeton par défaut n'est codé en dur.

Exemple pour une plateforme qui lit les médias et suit le breakout :

```bash
WEBHOOK_TOKEN_STATUS=<openssl rand -hex 32>
WEBHOOK_TOKEN_BREAKOUT=<openssl rand -hex 32>
WEBHOOK_TOKEN_MEDIA=<openssl rand -hex 32>
MEDIA_WEBHOOK_PREFIXES=praps2/media/,sondage_audio/
WEBHOOK_RATE_LIMIT_PER_MIN=300
```

Pour générer une valeur solide :

```bash
openssl rand -hex 32
```

Puis recréer le container csweb pour pick up la variable :

```bash
docker compose up -d --no-deps csweb
```

### Codes d'erreur

Tous les webhooks utilisent le même catalogue de codes (`error.code`) :

| HTTP | `error.code`            | Cause                                              |
|------|-------------------------|----------------------------------------------------|
| 400  | `invalid_body`          | JSON invalide ou champs requis manquants           |
| 400  | `invalid_dictionary`    | Nom de dict ne matche pas `^[A-Z0-9_]+$`           |
| 400  | `invalid_filename`      | Nom de fichier log non conforme                    |
| 400  | `invalid_action`        | Action inconnue                                    |
| 400  | `invalid_path`          | Média : chemin avec `..`, absolu, ou extension non autorisée |
| 403  | `forbidden_path`        | Média : chemin hors de `MEDIA_WEBHOOK_PREFIXES`    |
| 403  | `delete_disabled`       | Média : suppression désactivée (`MEDIA_WEBHOOK_ALLOW_DELETE`) |
| 404  | `not_found`             | Média : fichier ou dossier inexistant              |
| 413  | `content_too_large`     | Média : lecture > `MEDIA_WEBHOOK_MAX_BYTES` (lire par morceaux) |
| 401  | `missing_token`         | Header `Authorization` absent ou mal formé         |
| 401  | `invalid_token`         | Token reçu ne correspond pas                       |
| 403  | `file_not_readable`     | Fichier de log non lisible                         |
| 404  | `dictionary_not_found`  | Dict inexistant                                    |
| 404  | `file_not_found`        | Fichier de log inexistant                          |
| 405  | `method_not_allowed`    | Verbe HTTP non supporté                            |
| 413  | `body_too_large`        | Body POST > 64 KB                                  |
| 429  | `rate_limited`          | Quota dépassé (header `Retry-After` fourni)        |
| 503  | `server_misconfigured`  | Jeton du webhook non défini (500 avant 8.0.14 / 8.1.20), ou `MEDIA_WEBHOOK_PREFIXES` vide |
| 500  | `process_failed`        | `proc_open` impossible                             |
| 500  | `breakout_failed`       | Breakout terminé avec exit ≠ 0                     |
| 500  | `internal_error`        | Erreur DB / exception non spécifique               |

### HTTPS obligatoire en production

En production, exposer les webhooks uniquement via HTTPS (Let's Encrypt,
reverse proxy, etc.). Le Bearer token transite en clair sur HTTP.

### Journaux d'accès sans chemins de fichiers

Les applications CSPro envoient les médias avec le nom du fichier dans l'URL
(`/api/files/…/{clé}_ENTRETIEN.m4a/content`), et ce nom contient souvent la
clé du répondant. Depuis 8.0.14 / 8.1.20, la configuration Apache de l'image
et les modèles de reverse proxy (Apache et Nginx) écrivent `[path masked]`
pour `/api/files/` et `/file-manager/`, et ne journalisent plus le Referer.
Un reverse proxy déjà installé à partir d'un modèle doit être mis à jour à la
main (lignes `LogFormat` / `CustomLog`, ou `map` / `log_format`).

Le mieux reste de ne pas mettre la clé du répondant dans le nom des fichiers
côté CSPro (identifiant opaque, correspondance gardée dans les données).

## Customisation

### Webhook Custom

Créer `custom-webhook.php` à la racine et réutiliser le helper partagé pour
hériter automatiquement de l'authentification, du rate-limit, du capping
de body et du format de réponse uniforme :

```php
<?php
require_once __DIR__ . '/webhook_helper.php';

requireMethod(['POST']);
requireBearerToken();

$body = readJsonBody();
if (!$body || empty($body['dictionary'])) {
    respondError('invalid_body', 'Missing "dictionary" in request body.', 400);
}

// Logique custom : envoyer une notification Slack
$slack = 'https://hooks.slack.com/services/YOUR/WEBHOOK';
$ch = curl_init($slack);
curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode(['text' => "New case in {$body['dictionary']}"]));
curl_setopt($ch, CURLOPT_HTTPHEADER, ['Content-Type: application/json']);
curl_exec($ch);

respondSuccess(['notified' => true]);
```

## Monitoring

Ce que CSWeb garde comme traces des appels de webhooks :

| Trace | Où | Contenu |
|---|---|---|
| Passages de breakout déclenchés par webhook | `var/logs/<DICTIONNAIRE>_<date>-api.log`, lisible par `log-reader-webhook.php` | Sortie complète du passage |
| Appels du webhook médias | `var/logs/media-webhook.log` | Date, action, code HTTP, empreinte du chemin, IP (jamais le chemin) |
| Accès HTTP | Journal d'accès Apache ou Nginx | Méthode, URL (chemins de fichiers masqués), code, taille |
| État du breakout | `breakout-status-webhook.php` et la page **Breakout Health** | Cas collectés, traités, en attente, derniers passages |

## Troubleshooting

### Webhook Non Reçu

Vérifier :

```bash
# Firewall
curl http://your-server/breakout-webhook.php

# Logs Nginx/Apache
tail -f /var/log/nginx/access.log

# Logs CSPro (côté client)
```

### Token Mismatch (401)

```bash
# Vérifier le token côté serveur CSWeb (jeton du webhook, sinon jeton commun)
docker exec csweb-app printenv | grep -E 'WEBHOOK_TOKEN'

# Vérifier le token côté client (.env de Kairos / variable d'environnement
# de votre intégration). Les deux doivent être strictement identiques.
```

Réponse attendue en cas de mismatch :

```json
{
  "success": false,
  "data": null,
  "error": { "code": "invalid_token", "message": "Invalid token." }
}
```

### Timeout

Si webhook prend trop de temps :

```php
// Répondre immédiatement
http_response_code(202);
echo json_encode(['status' => 'accepted']);

// Traitement async
fastcgi_finish_request();
exec("php process-breakout.php {$dictionary} > /dev/null 2>&1 &");
```
